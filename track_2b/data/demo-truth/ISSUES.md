# Musterwil demo site – planted issues and traps

**Gemeinde Musterwil / Commune de Musterwil / Comune di Musterwil** is a fictional, trilingual (DE root, `fr/`, `it/`) municipal website. Klar. scans it in `make run`. It looks like a normal small Swiss municipal site but contains deliberately planted accessibility issues for criteria that need human judgement, plus correct "trap" elements that must **not** be flagged. Everything is invented: the municipality, the region "Aarenwald", people, addresses (`9999 Musterwil`), phone numbers (`032 000 …`), e-mails (`@musterwil.example`) and figures. All images are SVGs drawn for this site; there are no external resources (no CDN, web fonts, remote images or analytics) and no coat of arms or federal marks.

**Answer keys live outside the served folder.** This file and `issues.jsonl` are in `data/demo-truth/`; the pages they describe are in `data/demo-site/` (all `page` paths below are relative to it).

## Serve

```
python -m http.server -d data/demo-site 8000
# then open http://localhost:8000/   (file:// works too; all links are relative)
```

The HTML pages, SVG images, the PDF, this file and `issues.jsonl` (both in `data/demo-truth/`) are generated by `python -I scripts/demo_site/build.py` (stdlib only, deterministic); the CSS and JS in `assets/css/` and `assets/js/` are hand-written. Edit the content modules in `scripts/demo_site/` and rebuild rather than editing the HTML by hand. `python -I scripts/validate_testset.py` checks that every selector below matches exactly one element.

## Conventions

- Every planted issue and every trap has a `data-testid`; `[data-testid="…"]` matches exactly one element on its page. Testids are neutral names; verdicts appear only in this file and in `issues.jsonl`.
- `selector` `—` (JSON `null`) = page-level criterion (e.g. 2.4.2, 2.4.5, 3.1.1).
- `expected` uses the W3C ACT / EARL vocabulary: `failed` | `passed` | `cantTell` | `inapplicable`. `kind` = `issue` (planted defect) or `trap` (correct or exempt element; must not be reported as failed).
- 2.4.4 follows decision D1 of `data/testset/PROTOCOL.md`: programmatic context = the link's accessible name plus the enclosing sentence, the closest block container (ACT 5effbb), list item(s), table cell with its header cells and `aria-describedby` targets. **A preceding heading is not context** (H80 is advisory), so links disambiguated only by a card heading are labelled `cantTell` (strict ACT 5effbb reading: `failed`); links with no context at all (the "Kurz gemeldet" tiles) are `failed`.
- Error containers (`form-error-summary`, `form-plz-error`) exist empty and `hidden` in the static DOM; their text is injected by `assets/js/forms.js` when the form is submitted.
- `velo-aktion.html` is intentionally reachable only from the 4th news card on `index.html` (not in nav, sitemap or search index).
- **Set-level criteria (2.4.5, 3.2.3, 3.2.4; and 2.4.2 for titles duplicated across pages).** As in `data/testset/PROTOCOL.md`, the label applies to the *set of pages*; each language version (German root, `fr/`, `it/`) is one set. Rows for these criteria have `scope = set`, their `expected` is the outcome of the whole set on every page where the row applies, and `deciding_page` names the page that decides it. The German set is designed to fail each of them because of one page: 2.4.2 → `oeffnungszeiten.html`, 2.4.5 → `velo-aktion.html`, 3.2.3 → `abfallkalender.html`, 3.2.4 → `sitemap.html`; the French and Italian sets pass. `kind = set` marks a row whose page itself is fine (or exempt) but which carries the set outcome; the deciding page keeps `kind = issue`.

## Barrierefreiheitserklärung – deliberate gaps (informational)

`barrierefreiheit.html` (and the FR/IT translations `fr/accessibilite.html`, `it/accessibilita.html`) is a realistic accessibility statement (scope, conformance status "teilweise konform", list of non-accessible content, feedback form). Its gaps are **not a WCAG success criterion**; they are statement gaps measured against the EU 2018/1523 model statement and eCH-0059 practice. They are listed here for information only and are not part of `issues.jsonl`.

- No date of the last review: only the creation date (3 March 2025) is given; there is no "last reviewed/updated" date.
- Feedback only through a web form: the statement's feedback section offers no e-mail address or phone number for accessibility feedback; in DE and IT the form's send control is itself a non-focusable `<div class="btn">` (see the 4.1.2 rows), so keyboard users cannot use the only channel.
- Known problems are missing from the list of non-accessible content: the auto-rotating carousel without pause (freizeit.html), the online-counter form errors (online-schalter.html: "Fehler", positive tabindex, no review step) and the "Mehr" link texts.
- No enforcement / ombudsperson procedure: the statement does not say where to turn if the feedback is not answered satisfactorily (EU 2018/1523 model "enforcement procedure"; eCH-0059 practice of naming a contact and a conciliation/ombuds office).
- Assessment method given only as "Selbstbewertung" without scope or sample pages.
